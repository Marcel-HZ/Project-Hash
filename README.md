# Hash 函数原理与实战教学项目

交互式 Python 哈希函数教学项目。运行时先输入一个明文，然后按步骤跟踪该明文的编码、加密、加盐、派生、校验和彩虹表破解全过程。

## 哈希函数原理

### 1. 数学定义与基本逻辑

哈希函数（Hash Function）是将任意长度的输入数据映射为固定长度摘要的函数。对于本项目采用的 SHA-256，可以将其形式化表示为：

```text
H: {0,1}*  →  {0,1}^256 ,    h = H(m)
```

其中 `m` 表示输入消息，`{0,1}*` 表示所有有限长度的二进制串，`h` 表示输出的 256 位哈希摘要。输入可以是文本、文件或其他二进制数据；在计算前，程序需要先将其转换为字节序列。无论输入长度如何，SHA-256 的摘要长度始终为 256 bit，即 32 byte。

哈希运算的核心不是对数据进行可逆加密，而是通过确定性的数学变换，将输入压缩为固定长度的摘要。理想的密码学哈希函数应满足以下性质：

- **确定性（Determinism）**：对于同一算法和同一输入，输出始终相同，即 `H(m) = H(m)`。因此，摘要可以用于重复计算和结果比对。
- **单向性（Preimage Resistance）**：给定摘要 `h`，在计算上难以找到满足 `H(m) = h` 的输入 `m`。这并不意味着数学上绝对不存在逆向输入，而是指在现实计算资源下难以完成。
- **抗第二原像性（Second-preimage Resistance）**：给定一个输入 `m1`，难以找到另一个不同输入 `m2`，使得 `H(m1) = H(m2)`。
- **抗碰撞性（Collision Resistance）**：难以主动找到任意两个不同输入 `m1` 和 `m2`，使得 `H(m1) = H(m2)`。由于输出空间有限，碰撞在数学上必然存在；安全性要求的是寻找碰撞在计算上不可行。
- **雪崩效应（Avalanche Effect）**：输入发生极小变化（例如改变一个比特）时，输出摘要应出现大范围、近似随机的比特变化。对于 256 位摘要，理想情况下平均约有一半输出比特发生变化。

因此，哈希函数适合进行摘要计算和完整性验证，但不能直接承担数据保密任务。哈希值也不是密文，不能通过“解密”操作还原原始明文。

### 2. SHA-256 的组成部分

本项目的基础哈希步骤使用 SHA-256。SHA-256 属于 SHA-2 算法家族，其内部采用 Merkle–Damgård 迭代结构，主要由以下部分构成：

1. **消息预处理与填充**：将输入消息转换为比特串，在末尾追加一个 `1`，随后追加若干个 `0`，使当前长度满足模 512 后余 448 bit；最后追加一个 64 bit 的消息原始长度字段。经过填充后，消息总长度是 512 bit 的整数倍。
2. **消息分块**：将填充后的消息划分为若干个 512 bit（64 byte）的消息块，依次处理。每个消息块包含 16 个 32 bit 的初始字。
3. **初始哈希值（IV）**：算法使用 8 个 32 bit 的初始状态字作为起始值。这些常量由前 8 个素数平方根的小数部分确定，用于初始化内部状态。
4. **消息扩展**：将每个消息块的 16 个初始字扩展为 64 个 32 bit 的消息调度字 `W0, W1, ..., W63`。扩展过程结合循环右移、右移和模 `2^32` 加法，使各轮运算使用不同的消息信息。
5. **压缩函数与轮迭代**：每个消息块执行 64 轮迭代。运算使用 8 个 32 bit 工作变量、消息调度字、轮常量 `Kt`，以及选择函数、多数函数和若干位运算函数。
6. **摘要输出**：一个消息块处理结束后，将工作变量与当前哈希状态按模 `2^32` 相加，得到下一块的输入状态。所有消息块处理完毕后，将 8 个 32 bit 状态字依次拼接，形成 256 bit（32 byte）的最终摘要。

### 3. 核心数学运算

SHA-256 的内部运算以 32 bit 无符号整数为基本单位。加法均按模 `2^32` 计算，即：

```text
a +₃₂ b = (a + b) mod 2^32
```

（`+₃₂` 表示模 `2^32` 加法，为避免与异或混淆，未使用 ⊕ 符号。）这种处理保证每个运算结果仍处于 32 bit 范围内。算法还大量使用异或（XOR）、按位与（AND）、按位取反（NOT）、循环右移（ROTR）和逻辑右移（SHR）等操作。

压缩函数中的主要逻辑函数如下。设 `x, y, z` 均为 32 bit 字：

```text
Ch(x, y, z)  = (x AND y) XOR (NOT x AND z)
Maj(x, y, z) = (x AND y) XOR (x AND z) XOR (y AND z)

Σ0(x) = ROTR^2(x)  XOR ROTR^13(x) XOR ROTR^22(x)
Σ1(x) = ROTR^6(x)  XOR ROTR^11(x) XOR ROTR^25(x)
```

其中，`Ch` 根据 `x` 的对应比特，从 `y` 和 `z` 中选择比特；`Maj` 对三个输入的对应比特进行多数选择；`Σ0` 和 `Σ1` 则通过多组循环右移与异或运算混合比特信息。

每轮迭代根据当前工作变量计算两个中间值（以下均为模 `2^32` 加法）：

```text
T1 = h + Σ1(e) + Ch(e, f, g) + Kt + Wt   (mod 2^32)
T2 = Σ0(a) + Maj(a, b, c)                (mod 2^32)
```

随后更新 8 个工作变量：

```text
(a, b, c, d, e, f, g, h) ← (T1 + T2, a, b, c, d + T1, e, f, g)   (mod 2^32)
```

这里的 `Kt` 是第 `t` 轮使用的 32 bit 常量，`Wt` 是当前消息块扩展得到的第 `t` 个消息调度字。上述更新连续执行 64 轮，使消息内容逐步影响整个内部状态。每个消息块完成后，再将工作变量反馈到哈希状态，供后续消息块继续计算。

### 4. 完整运算流程

从程序执行角度看，SHA-256 的计算过程可以概括为：

1. **输入与编码**：接收明文或文件数据。对于字符串，先按照指定字符编码（本项目使用 Python 字符串的 `encode()` 默认 UTF-8 编码）转换为字节序列。
2. **填充与分块**：按照 SHA-256 规范追加填充位和原始长度字段，再切分为 512 bit 的消息块。
3. **初始化状态**：载入 8 个初始哈希状态字。
4. **扩展消息**：针对当前消息块生成 64 个 32 bit 消息调度字。
5. **执行压缩**：以 8 个工作变量为状态，结合 64 个轮常量和逻辑函数执行 64 轮运算。
6. **累积状态**：将本块运算结果与原哈希状态按模 `2^32` 相加；若仍有消息块，则继续处理下一块。
7. **生成摘要**：拼接最终的 8 个状态字，得到 32 byte 的摘要。程序可进一步将其表示为 64 位十六进制字符串，或使用 Base64 转换为文本形式。

本项目通过 `hashlib.sha256(data).digest()` 调用 Python 标准库实现 SHA-256。`digest()` 返回原始 32 byte 摘要；`.hex()` 将其转换为十六进制字符串；Base64 则将摘要字节编码为可打印文本。这两种表示方式只是同一摘要的不同编码形式，不会改变哈希结果。

### 5. 与项目中其他步骤的关系

哈希函数是本项目后续演示的基础，但需要区分哈希、编码、加盐和密钥派生等不同操作：

- **SHA-256 基础哈希**：直接计算 `h = H(m)`。相同输入必然得到相同摘要，适合演示基本哈希过程与雪崩效应。
- **Base64 编码**：将二进制数据转换为文本表示，不提供加密或哈希保护。对哈希摘要进行 Base64 编码，只是改变其表示形式，不能增强摘要的安全性。
- **盐值机制**：生成随机盐值 `s`，再计算 `h = H(s ‖ m)`，其中 `‖` 表示字节串拼接。本项目示例采用 `salt + password.encode()`。不同盐值会使相同密码产生不同结果，从而降低预计算彩虹表的有效性。盐值通常与摘要一起保存，并不需要作为秘密信息保管。
- **PBKDF2-HMAC-SHA256**：用于从密码派生密钥，而不是简单地执行一次 SHA-256。它以密码和盐值为输入，使用 HMAC-SHA256 作为伪随机函数，并重复计算指定次数，以提高每次密码猜测的计算成本。迭代次数、盐值和派生密钥长度都是重要参数。
- **文件校验和**：对文件内容计算 SHA-256 摘要。文件发生变化时，摘要通常也会显著变化；将重新计算的摘要与可信来源提供的摘要比较，可以检测传输错误或内容篡改。校验和本身不能证明摘要来源可信，若攻击者能够同时替换文件和摘要，还需要数字签名或可信认证机制。
- **彩虹表攻击演示**：通过预计算候选输入及其哈希关系，以时间换取存储空间，尝试从已知摘要中定位候选密码。随机盐值使预计算结果难以跨用户复用；PBKDF2 等慢速密钥派生方法则提高每次猜测的成本。

### 6. 现实应用场景

1. **密码存储与身份验证**：服务端不应以明文形式保存用户密码。实际系统通常为每个密码生成独立随机盐值，并使用 PBKDF2、Argon2 等专用密码哈希或密钥派生方案保存派生结果。用户登录时，系统使用相同参数重新计算并比较结果。单次快速 SHA-256 不适合作为现代密码存储方案。
2. **文件完整性校验**：软件发布方可以公布安装包的 SHA-256 摘要。用户下载文件后自行计算摘要并比对，以发现文件损坏或传输过程中的意外修改。若需要防止恶意替换，还必须通过可信渠道获取摘要，或使用数字签名验证发布者身份。
3. **数字签名**：数字签名方案通常先对较长消息计算哈希摘要，再对摘要执行签名运算。验证方重新计算消息摘要并验证签名，从而检查消息完整性及签名者身份。哈希函数在此过程中负责生成固定长度摘要，签名算法负责身份认证和签名验证。
4. **区块链与数据结构**：区块链系统使用哈希摘要关联区块、校验数据，并在部分系统中构建 Merkle 树，以摘要形式组织大量交易数据。数据变化会沿哈希关系反映到上层摘要，从而支持完整性验证。
5. **内容去重与版本管理**：系统可以使用文件或对象的哈希摘要作为内容指纹，辅助识别相同内容、检测变化以及进行缓存管理。实际应用仍需考虑哈希碰撞的理论可能性，并在关键场景中进行额外校验。

综上，哈希函数通过固定长度摘要、迭代压缩和位运算实现对输入数据的确定性映射。SHA-256 展示了密码学哈希的基本机制；盐值与 PBKDF2 则进一步面向密码存储场景提高攻击成本；文件校验和、数字签名及区块链等应用利用摘要实现完整性验证或数据关联。应根据具体安全目标选择算法，不能将普通哈希、可逆加密和数据编码混为一谈。
